Unreleased

Documentation layout, the changelog itself, and playground fixes.

Fixed: the reference pages linked to nowhere

The documents link to each other by filename, which is how they read from disk. Served at their own routes, architecture.html from /ui/changelog resolved to /ui/architecture.html and 404ed; the architecture note had no route at all and was unreachable from the UI. The whole directory is now served at /ui/docs/, so those links resolve in the browser exactly as they do on disk, and the short paths redirect there. A test crawls every link on every page and fails on a dead one.

Configuration documents itself

  • docs/properties.html lists all 48 settings with their defaults, types and constraints, generated from app/config.py and served at /ui/properties. Every field carries its own description and group, so a setting added to the model appears in the page automatically; a table maintained by hand drifts the first time someone forgets.
  • .env and .env.example were cut back to what is actually configured. They had been repeating three dozen values that already matched their defaults, which is noise that goes stale silently: change a default in code and the file quietly keeps overriding it with the old one. A test now fails if either file sets a value to its default.
  • Nothing is required to start. Two values become mandatory only with the feature that needs them: OPENAI_API_KEY for the OpenAI provider, API_KEYS once authentication is on.

The playground became a chat

  • The conversation is on the right and everything behind the last decision is on the left. Enter classifies, Shift+Enter adds a line, and the domain is picked in the chat itself.
  • Every turn keeps its own details. A compact snapshot of the decision is recorded with the turn, so clicking a reply from last week shows what actually happened then. Re-classifying an old turn instead would be slower and would quietly change its answer once the catalogue moved on, which is the wrong thing to show beside a historical conversation. Details are kept whether or not the caller asked to see them, so a turn recorded through the plain API is as inspectable as one from the UI.
  • Sessions are now reachable: a row on the sessions page opens that conversation, with its turns and the domain it happened in.

Fixed: a change of subject was absorbed by the previous turn

The contextual retry classifies the previous question plus the new one, which means the previous question alone can carry the match. Asked after "summarize contract C-1042", "what is the weather today" came back as CONTRACT_SUMMARY at 0.66 confidence, where on its own it was correctly UNKNOWN at 0.34. This was found by running the demo, not by a test.

Two guards now apply, the same shape as the ones on the auto strategy. The retry only runs for text that reads as referential, a pronoun or a fragment too short to stand alone, and its result must clear the threshold by a margin. "and for Oracle" is still rescued; "what is the weather today" is not.

A recorded demo

  • docs/demo.html is a real conversation against a running service, interactive: click any reply to see how that turn was decided. docs/demo.gif is the same run as an animation.
  • Both are produced by scripts/build_demo.py from one live recording, so neither can drift from what the service does. It clears its sessions first: re-recording against a service that already held those conversations carried entities in from the previous run and produced a transcript that never happened.

Fixed in the playground

  • A long intent name overlapped the confidence beside it. Grid items default to min-width: auto, so the name refused to shrink below its own width and ran into the next column; underscore-joined names do not break on their own either. The cell may now shrink and the name wraps.
  • A cached stylesheet survived a deploy. Browsers held the old app.css, so a style change was simply invisible until a hard refresh. Static assets are now requested with the file's modification time, making a changed file a new URL. This was found the honest way: the dots below were correct in the file and absent on screen.

Confidence at a glance

  • The confidence breakdown and the ranked intents each carry a coloured dot: green above 80%, amber 50 to 80%, red below. Ranked intents are banded by best similarity, so a lexical-only hit with no semantic support reads as red rather than looking like a near miss.
  • The thresholds live in one filter, so a dot in a table and the headline number cannot drift apart. The dot sits beside the value and never replaces it, because colour alone is not readable to everyone.

Documentation

  • Documentation moved to docs/. The architecture note and the generated API reference now live together rather than scattered at the repository root. The generator, the /ui/api route, the Docker image and the freshness test all follow the new path. README.md stays at the root: it is the file people and tooling look for there, and pyproject.toml declares it as the project readme, so moving it would break the package build.
  • This changelog, served at /ui/changelog and linked from the navigation.

MCP tools, per-query strategy, and a UI pass

Commit 7974177

An intent can be wired to an MCP tool

A registry of Model Context Protocol tools, stored in the same database as everything else. A tool is registered by hand or imported from a server's tools/list response, and a bound intent makes every classification report the exact call that would satisfy it: server, tool, transport, endpoint, and the arguments mapped from the extracted entities.

Arguments are matched against the tool's JSON Schema rather than the intent's, because they are not the same contract. Anything the tool does not declare is reported as unmapped instead of being sent, a missing required argument leaves the call not ready, and a binding whose tool was deleted reports that plainly rather than quietly losing the call a caller was waiting for.

Nothing is executed, and that is a seam rather than a wall. The service resolves and reports the call; the caller makes it, because the caller owns the credentials and the blast radius. Real invocation is one protocol implementation away, and the default refuses every call, so adding a client cannot surprise anyone with something already having run.

Choosing a retrieval strategy per query

DEFAULT_STRATEGY=auto answers with hybrid fusion and falls back to the alternates only when hybrid cannot place a query, reporting which one resolved it. Two rules keep that from becoming a way to say yes to everything. Both came from measurement after the first attempt got it wrong.

RuleWhat went wrong without it
Fallbacks must use dense retrieval A lexical-only pass cannot apply the minimum-similarity floor. On a single shared word it matched "what is the weather today" to CONTRACT_EXPIRY at 0.86 confidence.
A rescue must clear the threshold plus a margin Without one, accuracy rose while UNKNOWN detection fell from 90% to 70%. For a system that routes to tools, that trade means confidently calling the wrong one.
StrategyTop-1UNKNOWN detectionValid queries refused
hybrid_rrf (default)90.6%90%3.1%
auto, no margin93.8%70%0%
auto, margin 0.1093.8%90%0%

With the margin, auto beat hybrid on every measure. That is 42 cases: enough to choose a margin, not enough to change a default, so hybrid still ships as the default.

Domains state the role the assistant should adopt

Generated system instructions now open with the role the domain implies, because how to act is the first thing the extractor needs to know. Contractual work gets a contracts and legal analyst; carts and checkout get an e-commerce shopping assistant. The same sentence means different things to each.

Interface

  • Pages for the MCP registry, every intent across domains, and recent conversations.
  • Navigation marks the current page; index health and the audit feed refresh on a timer.
  • Flash messages became toasts, so a message no longer pushes the page down as you work.
  • Confidence is colour-coded: green above 80, amber 50 to 80, red below 50, with a plain-language note, so the colour and the number say the same thing.

Fixed

  • Updating an intent's tool mapping corrupted the record. Pydantic's model_copy does not re-validate, so a nested tool supplied as a dictionary was stored unvalidated and every later read of that intent failed, including both UI pages and tool routing. It was unreachable from the tests because none of them updated a tool.
  • The MCP read model shadowed a parent property, warning on every import. It is a computed field now.

Docker build and first-run experience

Commits c1e9144, 2222c41

  • The image did not build. pyproject.toml declares README.md as the project readme and the build backend validates that the file exists, but it was never copied in. Copying it fixed the build.
  • Rebuilds re-downloaded the embedding model. The 67 MB bake sat below the source copy, so editing one line invalidated it. Moving it above turned a rebuild into one second.
  • A fresh clone could not start. Compose required a .env that is gitignored, so it failed before running. It is optional now, and the application's own defaults apply.
  • Seeding through docker compose exec broke the running server. Embedded Chroma is single-writer: the write succeeded, but the server kept its own view and failed to read the new vectors until restarted. SEED_ON_STARTUP seeds in the server's own process instead, and the documented quickstart is now one command.
  • The test suite aborted about one run in eight with a native crash in Chroma's Rust bindings during interpreter shutdown. Pinning chromadb==1.5.2 and leaving before finalization made twelve consecutive runs clean, with the result summary and exit code preserved.

Generated configuration

Commit b048bca

  • Domain instructions can be drafted by the LLM from a name and a one-line description, then refined by hand. An administrator knows their domain, not prompt engineering.
  • Intents too, in auto mode, each with a tool mapping, entity schema and training examples. Generating the examples alongside is what makes the difference: retrieval matches against examples, so an intent without them can never be returned, and a catalogue of example-less intents would classify nothing.
  • Generated configuration is ordinary configuration. It lands in the same collections as hand-written entries and is edited through the same endpoints and screens. Existing names are skipped rather than overwritten, so running auto mode twice extends the catalogue instead of destroying work.
  • Model output is treated as untrusted input throughout: names coerced to the pattern the model enforces, schemas filtered to declared types, examples deduplicated the way the index would, and anything unusable reported rather than saved.
  • An offline rule-based provider (LLM_PROVIDER=mock) answers every generation task, so the whole flow runs and is tested without an API key.

Multi-turn conversations

Commits 1032530, 9480820

  • Turns sharing a session id inform each other. A follow-up that cannot stand alone is retried with the previous question, and the contextual result is kept only if it actually resolves, so context can rescue a turn but never overrule a confident answer.
  • Entities named earlier carry into a later intent that declares the same entity, and only that intent, so nothing leaks into a tool with no use for it.
  • Conversations live in the same store as the catalogue, with a per-session size cap and a time limit.

Entity extraction, tool routing, and hardening

Commit 6a21de2

  • Entity extraction, running only after a confident match and never for UNKNOWN, because pulling arguments out of a request the system did not understand produces confident nonsense.
  • Tool routing that reports the call and its validated arguments without making it.
  • API-key authentication with nested scopes and a per-key domain boundary; Prometheus metrics; an append-only audit log that does not record query text unless asked; request ids threaded through responses, logs and traces; optional OpenTelemetry.
  • Six named retrieval strategies with deterministic assignment, and an evaluation dashboard that runs the held-out set against the live catalogue.

The classifier

Commits b8d1867, c2b39af

  • Domain-aware intent classification: dense retrieval over FastEmbed vectors in Chroma and BM25 lexical retrieval, fused with Reciprocal Rank Fusion, aggregated from examples into intents, then scored for confidence.
  • UNKNOWN when nothing is close enough, which matters most: a wrong intent in an agentic system means calling the wrong tool.
  • A management interface and a playground that shows every stage of the pipeline, a seeded demo catalogue, and an evaluation harness with threshold sweeping.

Adding an intent never requires retraining a model. That is the property the whole design protects.
