Start here

One endpoint does the work. Everything else configures it or explains it.

curl -X POST http://localhost:8000/api/v1/classify \
  -H 'content-type: application/json' \
  -d '{"domain": "contract", "text": "Show me all active contracts with Microsoft"}'
{
  "domain": "contract",
  "intent": "CONTRACT_SEARCH",
  "confidence": 0.88,
  "entities": { "counterparty": "Microsoft", "status": "ACTIVE" },
  "tool": {
    "name": "search_contracts",
    "version": "v1",
    "arguments": { "counterparty": "Microsoft", "status": "ACTIVE" },
    "missing_required": [],
    "ready": true
  },
  "reason": null,
  "top_intents": [ ... ],
  "latency_ms": 11.0,
  "request_id": "5f3c..."
}
Read intent together with reason. When nothing matches well enough the intent is UNKNOWN and reason says which rule fired: low_confidence, low_similarity or no_examples. That is a real answer, not an error. For an agent, a confident wrong intent invokes the wrong tool.

Conversations

Pass a session_id and turns inform each other. The same id across calls is one conversation; a different id is a different one. Sessions are also scoped per domain.

POST /api/v1/classify  {"domain":"contract","text":"Show me all active contracts with Microsoft","session_id":"s-1"}
  -> CONTRACT_SEARCH   entities {counterparty: Microsoft, status: ACTIVE}

POST /api/v1/classify  {"domain":"contract","text":"and for Oracle","session_id":"s-1"}
  -> CONTRACT_SEARCH   entities {counterparty: Oracle, status: ACTIVE}
     context.used_for_retrieval = true
     context.retrieval_text = "Show me all active contracts with Microsoft and for Oracle"
     context.carried_entities = ["status"]

Two mechanisms, both reported in context so nothing is hidden:

  • Contextual retrieval. A turn that comes back UNKNOWN is retried as the previous question plus the new one, and the contextual result is kept only if it resolves. Context can rescue a follow-up; it can never overrule a confident answer.
  • Entity carry-over. A value named earlier fills an entity the new turn did not mention, but only where the new intent declares that entity.

Send "use_context": false to treat one turn as standalone while still recording it. GET /api/v1/sessions/{id} shows a conversation, DELETE forgets it.

Entities and tools

Extraction runs only after a confident match, never for UNKNOWN, and is the only place this service calls a language model. Whatever the model returns is treated as untrusted input: values are coerced to the type the intent declared, enums are normalised to the declared spelling, dates become ISO 8601, and any key the intent did not declare is dropped. Rejections are listed in entity_extraction.rejected.

A required entity that was not found leaves the tool call ready: false with the missing names listed, rather than calling a tool with a hole in its arguments. The service reports the call and never performs it.

Turn extraction on globally with ENTITY_EXTRACTION_ENABLED=true, or per request with "extract_entities": true. Set LLM_PROVIDER=mock to run the whole flow offline with a rule-based extractor and no API key.

Errors

Failures return a single shape, carrying the request id so a report can be traced:

{"error": {"code": "not_found", "message": "domain 'ghost' not found", "request_id": "5f3c..."}}
StatusCodeWhen

Authentication

Off by default. Enable with AUTH_ENABLED=true and define keys as secret:domains:scopes, comma separated:

API_KEYS=ops-key:*:admin, contract-svc:contract|legal:classify, dashboard:*:read

Send the key as X-API-Key or Authorization: Bearer. Scopes nest: admin > write > read > classify. The domain list is a hard boundary, not a filter: a key scoped to one domain cannot classify against, read, or even enumerate another. /health needs no credential, because a probe that requires a secret stops working when the secret rotates.

Draft this domain's intents with the LLM, with their examples. Auto mode. Intents are created and their examples indexed, so the domain is classifiable straight away; everything is then editable exactly like a hand-written intent. Names that already exist in the domain are skipped and reported rather than overwritten. Pass ``dry_run: true`` to see the proposal without writing anything.
